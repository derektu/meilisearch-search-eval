# 各項調整解決什麼問題

這些方案分別處理「寫法不同」「詞被拆開」「只記得詞的一部分」三類搜尋問題。命中更多不一定較好；能找到要找的內容，也要排除只含分散字的文件。報告中的「正例」是應該找到的文件，「負例」是不應該找到的文件。

### B0：原廠設定，作為比較起點

使用官方 Meilisearch release，文件與查詢直接交給引擎。它提供後續方案的比較基準，本身沒有額外調整。

### B1：不同寫法，整理成相同的搜尋文字

| 處理項目 | 例子 | 使用者看得到的效果 |
| --- | --- | --- |
| 全形／半形 | `ＡＩ`、`AI`；`００５０`、`0050` | 全形輸入可與半形內容對應，0050保留前導零 |
| 英文字母大小寫 | `CoWoS`、`cowos` | 大小寫使用同一搜尋表示 |
| 繁簡字 | `台积电`、`台積電`；`期限溢价`、`期限溢價` | 不必先確認文件使用繁體還是簡體 |
| 常見字形差異 | `臺積電`、`台積電` | 臺／台使用同一搜尋表示 |
| 空白格式 | `台積電　 法說`、`台積電 法說` | 全形空白、連續空格、Tab與換行整理成一般空白 |

空白整理保留字與字之間的分隔：`觀 光`保留中間空白，並不變成`觀光`。寫法一致化也不等同於同義詞或公司別名。

整理只用在搜尋，文件文本保留原貌。

這些是B1的處理規則，不代表每一項都在官方引擎上單獨產生額外命中。整組B1在真實測資補回兩組既定正例，包含`台积电`與繁簡字形不同的`期限溢價`。

### C1：縮小引擎，搜尋結果作控制比較

Chinese-only source build保留中文相關功能，提供較精簡的引擎建置。它沒有額外增加詞彙或匹配規則。

本測資中，C1與官方B1的逐題命中ID與排序相同。這組的用途是分開看引擎建置與詞庫的影響，不以它宣稱搜尋品質或速度提升。

### B2：讓常用詞以完整詞彙參與搜尋

COCT提供繁體詞目與詞頻，讓`觀光`、`資安`、`半導體`等詞能被辨識。

- 查`觀光`，能找到觀光旅遊的文件，排除只含`直觀`和`賣光`的分散字例子。
- 查`資安`，能排除只含`安全的資產`的例子。
- 真實測資中，`觀光`的結果由6份縮至1份，保留既定正例；`資安`由10份縮至2份，同樣保留既定正例。

這組最明顯的收益是減少散字誤命中。詞內片段則有取捨：把`半導體`辨識為完整詞後，查`導體`可能找不到它。合成測資的明確負例誤收由C1的20組降到B2的3組，但正例命中也由37/38降到32/38；兩個數字需要一起看。

### B3：已經辨識完整的詞，不再細拆

第一輪得到`台積電`、`伺服器`時，保留這些完整詞，不再細拆成`台積／電`、`伺服／器`。

這讓詞界清楚，但不會自動支援詞內搜尋。單獨這項調整在本次合成測資沒有增加通過題數：B2與B3皆為14/22。它也不能代替片段召回。

### B4：只記得詞的一部分，也能找到，而且必須連續

| 查詢 | 應找到的內容 | 應排除的內容 |
| --- | --- | --- |
| `半導` | `半導體` | `半年過後導師安排體驗活動` |
| `導體` | `導體`與`半導體` | 只有分散的導字、體字 |
| `服器` | `伺服器` | 服與器分散在不同位置 |
| `股` | `個股`、`股票` | 不含股字的文件 |
| `金` | `自由現金流量` | 不含金字的文件 |
| `觀光` | 連續的`觀光` | `直觀…賣光`、`觀 光`、`觀、光` |

多詞仍可分開出現：`台積電 法說`要求兩個片段都在同一文件，各片段自身必須連續。引號要求整段連續，例如`"觀光產業"`。

B4以獨立片段索引補回原本未被引擎找到的文件，再檢查字面連續性。合成測資達到38/38正例、0組明確負例誤收，22/22題完整通過。

B4是記憶體參考方案；通過這批題目不代表通用排序、大資料效能或中文錯字容忍都已解決。
