# 比較方法與結論邊界

這個實驗把正規化、主詞庫、二次切分與片段查詢分開比較。所有方案共用固定 dataset 與 gold，結果區分 token、文件 membership、排序、高亮位置與成本，避免把某一層通過當成完整搜尋已完成。

## B0–B4 的固定意義

| 組別 | 行為 |
| --- | --- |
| B0 | Stock Meilisearch，不套應用程式文字正規化 |
| B1 | Stock Meilisearch＋相同應用程式正規化 |
| B2 | 外置 COCT 新聞詞頻主庫＋正規化＋原 Charabia 二次切分 |
| B3 | 相同外置 COCT 主庫＋正規化，停用二次切分，保留 Jieba 第一輪詞界 |
| B4 | B3＋獨立連續片段召回／驗證；參考實作的能力與整合層級需另外標示 |

COCT 全詞頭送進 Meilisearch dictionary API 是額外的 `diagnostic-full-dictionary-api`，不屬 B0–B4；API 沒有頻率，並未替換 Jieba 主庫。歷史 B0 未測量，不得拿 B1 數值補入。新倉庫重跑另記 run id，不混入歷史數字。

固定上游引擎版本／commit、Charabia／jieba-rs 版本、feature／target／toolchain、binary SHA256、外置詞庫 SHA256，以及文件／查詢／設定 hash。B0/B1 固定同一 stock binary；B2/B3 固定同一外置 binary，只有二次切分開關不同。換檔載入證明、缺檔／壞檔行為與正式 App 啟動整合是各自的證據，不互相替代。

正規化為同一函式：完整 NFKC、ASCII 小寫、OpenCC 1.4.2 s2t／t2tw 字形轉換、臺→台與 Unicode White_Space 合併／trim；不做公司別名、同義詞或地區用詞替換。原始顯示內容保留。COCT 使用新聞 raw count；碰撞加總後零值取 1，此政策不從 gold 推導。

## Gold、開發集與 holdout

`zh-semantics-v1` 的 23 文件／22 查詢、38 expected／468 forbidden 曾在候選實作前固定，但這批案例之後已用於診斷及調整方案，因此仍是**開發集**。`real-34` 的 34 文件／60 查詢也屬已反覆查看的開發資料；沒有獨立保留集成績。

每次比較前凍結輸入與 hash。看到失敗後可以修方案；若修改案例或期望，需另立 dataset 版本並說明理由，不能把改 gold 後的 pass 記為原版本改善。詞庫準備程式不讀 query/gold；不能只從失敗題挑出詞來稱作通用詞庫效益。

未來 holdout 應先由未參與當輪修正的人標註權利清楚的台灣一般／科技／財經文本，凍結後才執行；不得在同一輪依其失敗調參再保留 holdout 名義。所有新詞、公司／產品名與輸入法語料偏好都應在獨立題上確認。

`expectedIds` 是應命中文件，`forbiddenIds` 是明定不得命中文件，`expectZero` 是整題不得有結果。**未標註不是 irrelevant**。real-34 沒有 forbidden pairs，所以只能在已標註範圍說明正例 miss／零命中違反；不能直接用完整命中清單算 precision。公開合成集則每題完整標註 23 份文件。

## 連續片段與多詞

每個查詢片段必須在同一搜尋欄位連續出現；「半導」可命中「半導體」，不可用「半年」及「導師」分散拼字。「股」須能定位到「個股」內的股，不能靠同文件其他「股票」的股冒充成功。多個明確查詢詞維持 AND，可出現在文件不同位置；引號片語要求正規化原文連續。

COCT 已切出的多詞，例如「觀光／產業」，可以維持多詞 AND。未收短片段若變成相鄰漢字單字，參考方案將它們合併以保留連續性；這只是明訂的候選規則，不是所有自然語句分詞問題都已解決。

「岸風」跨「離岸／風電」詞界的字面連續情形、買股等輸入、中文 fuzzy 與中英混合 typo／prefix 行為仍需確認；未有 gold 的探索題只報結果，不報 pass／fail。詞內片段與一般全文 substring 規則不能在未說明時互換。

## 評估分層

- Token probe 說明哪一層拆詞；完整 Meilisearch 的索引／查詢行為另外實測。
- Membership 看完整文件 ID 集合，固定 limit 並避免截斷；另保留各項 missing／forbidden，而不是只報總命中數減少。
- 排名比較的兩個候選都必須存在；缺一個是不可評估，不得因完整詞獨佔 rank1 就 pass。
- 原文位置需查實際詞內位置、UTF-8 byte 與 UTF-16 原文範圍映射；三個合成映射案例通過，不等於已驗證產品 UI 全部高亮。
- 成本分索引初始化、詞庫載入、查詢時間、資料規模與 index 大小。小資料單次比較不推論大規模或跨機效能。

## 歷史 B4 的特別限制

舊 C（本倉庫稱 B4）是記憶體中的 Unicode 首字 posting，加上連續字面驗證，能獨立補回 B3 沒有的文件，不只是過濾 B3 結果。它針對含漢字查詢建立候選，保留 B3 已召回文件的順序，再追加補回者；沒有一般性的完整詞／片段打分規則。原「導體」排序案例兩候選都存在且順序正確，只證明這個案例，不能說完整排名功能已完成。

原 60 題的 **26 個不含漢字查詢直接繼承 B3 ID／順序**，藉此保留既有英文 typo 行為；這不是片段索引獨立通過英文評測，也不涵蓋中英混合 typo／prefix。參考實驗不代表 Meili 原生功能或完成產品後端整合。

B4 的記憶體函式計時包含已記錄 B3 結果作輸入，不包含現場 Meili HTTP 查詢。它不能和 B1–B3 HTTP p50／p95 當作速度比較，更不能宣稱 B4 端到端更快。新實作即使沿用 B4 名稱，也必須明記執行層級及是否真的呼叫引擎。

## 可公開的證據

公開輸出只包含自寫 fixture、查詢／gold、指標、ID 排名與 hash。第三方正文／標題摘錄／字幕、master key、DB、log 與個人絕對路徑留 ignored cache／results。原始來源與公開詞庫各有自己的條款；本倉庫 MIT LICENSE 不授權第三方資料，也不暗示 COCT 已可隨產品散布。

重現需要相同 snapshot，僅知道來源 URL 不足。每次新 run 要記錄實際輸入與執行版本；歷史報告與新倉庫結果明確分開。
